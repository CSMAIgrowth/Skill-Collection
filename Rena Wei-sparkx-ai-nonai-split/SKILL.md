# SparkX AI 与非AI 数据拆分（内部版）

适用对象：内部运营与分析人员；客户阅读版本使用 `sparkx-ai-nonai-report`。

## 目标与适用边界

解决：把某客户在指定时间段的广告数据拆成「AI 托管产生的」和「非 AI 产生的」，供效果对比、AI 占比汇报、AI 预算落点分析。

何时调用：用户（服务商侧运营/分析）提出 AI 与非AI 的任意指标对比、AI 占比、或「AI 的钱花在哪些品上」。

不适用：单个托管组的历史效果复盘（成员历史关系不可还原，见 references/pitfalls.md）；需要小时级 AI 数据的场景（平台 AI 指标只有按日真值）；窗口超过 90 天需拆窗分跑，不能一次出。

## 输入

必填：
- 客户连接：SparkX 连接器名，或 token 环境变量名（`--token-env`，约定存于 `~/.zshrc`）
- 日期窗口：`--start/--end`，YYYY-MM-DD，单窗 ≤90 天

可选：
- 店铺范围：`--profile-ids` 逗号分隔，缺省 = 该 token 全部授权店铺
- 口径：`--calibers campaign|product|both`，缺省 both
- 输出目录：`--out`，缺省 ./ai_split_out

系统自行取得：租户/店铺/币种/时区（首调 `get_user_authorized_context`，脚本自动）。不写死任何租户。
不能猜测的：日期窗口与店铺范围必须用户给出，脚本不会默认「最近30天」。

## 依赖与权限

- 直连 `https://mcp.sparkx.cn/mcp`（JSON-RPC over HTTP），需要一个有该客户数据权限的 PAT。
- python3 标准库即可运行，无第三方依赖。
- 行为边界：只读（广告报表查询），文件生成（--out 目录），无业务写入、无对外发送。跑大范围前建议先向用户报规模。

## 执行方法

1. `python3 scripts/ai_split.py --token-env <ENV> --start <D0> --end <D1> --calibers both --out <dir>`
2. 脚本自动：校验 token → 拉店铺清单 → 逐店取「活动×日」与「商品×日」全量（分页 500/页，确定性 orderBy）→ 逐店自检 → 落盘缓存（断点续跑）→ 聚合打印。
3. 判定规则（不可改写）：
   - 某活动当天算 AI ⇔ 当天该活动 `AISpend > 0`（平台为全有或全无，实测无部分值，等价于「当天开过 AI 则整天算 AI」）。
   - 商品行整行继承所在活动当天判定，不做比例分摊。
   - 品牌广告在商品层无行 → 未归属 = 「活动层减商品层」残差，按 AI／非AI 与活动类型拆出，禁止给商品行打 SB 标签（恒为 0，实测踩过）。
   - 比率一律分组求和后重算（CPC=花费/点击等），禁止平均行级比率。
4. 窗口 >90 天：拆多个不重叠窗口分别跑再合并。
5. 网络重试：脚本内置 307/308/429/5xx 与传输中断的指数退避重试；单店失败标记后继续其余店。

深入规则与证据：执行到「判定/分页/对平」任一步前读 [references/calibers.md](references/calibers.md)；遇到数据疑似异常（重复行、金额对不上、日期比较怪）时读 [references/pitfalls.md](references/pitfalls.md)。

## 输出

`--out` 目录：
- `口径A_活动日明细.csv`（每活动每天一行，含是否 AI 天）
- `口径B_商品日明细.csv`（每商品每天每活动一行，含 AI 花费份额分档）
- `口径B_未归属残差.csv`（未归属按分组×活动类型）
- `summary.json`（两口径聚合、分档、折美元账号级、四项校验、逐店校验明细）
- 按店缓存 `campaign_<id>.json` / `product_<id>.json`（断点续跑用）
- 控制台只打印聚合与校验，明细不进对话上下文（一页 500 行 ≈ 2.9 万 token）。

## 验收标准

四项校验任一不过不得交付（脚本自动执行并在 summary.json 记录）：
1. 翻页零副本 + 行级求和 = 引擎店级聚合（容差 0.5%）
2. AI 组花费合计 = 平台 AISpend 合计（实测差 0.000%）
3. 活动口径总数 = 商品AI + 商品非AI + 未归属（残差法应 ≈0）
4. 逐店校验零失败

需业务确认的：AI/非AI 效率差异的结论表述口径（对客时用分档表述），是否包含品牌广告取决于分析目的（活动口径含，商品口径单列）。
允许差异：跨店金额必须用平台折美元聚合；逐店本币相加会因日元等虚高，属口径错误不是容差。

## 异常与已知限制

- 缺输入：无 token/窗口 → 脚本直接退出并提示。
- 空数据：无授权店铺或窗口无花费 → 返回 0 行汇总，属正常。
- 权限不足：token 校验失败 → 明确报错退出，不重试。
- 工具失败：限流/网关抖动自动重试（同请求最多 6 次）；单店连续失败标记后跳过，重跑自动续。
- 大店单页可达 60–300 秒（服务端负载波动），全账号 30 天实际 40–60 分钟（沙箱单命令约 600 秒上限，须分段或后台跑）。
- 已知限制：当天零曝光的商品不出行；开关切换当天可能整天记为 AI（约 1 天宽差）；托管组历史成员关系不可还原。
