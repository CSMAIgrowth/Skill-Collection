# 技术广告案例转客户案例
## 输入
使用已获授权的技术复盘或结构化材料：客户疑问、目标、前后期原始指标、实际操作及时间、同期变化、结论证据。纯文本即可，无需私有工具或数据库。
缺原文或数字不能用行业常识补造。先核对时间、对象、币种、金额和比例分母；原材料冲突则并列并指出需要核对的项。
## 固定六段
1. 标题：突出具体问题、动作与观察到的后果；只有证据成立才用因果句。无因果证据写“调整后观察到……”。
2. 客户疑问：用客户能理解的问题和目标，不预设运营人员有错。
3. 数据证据：建议4–6行、5列（指标/前期/后期/变化/来源与限制）。材料不足时减少行数并说明缺口，不凑数；变化率与百分点分开，ACOS从总花费/总销售计算。
4. 可直接对客的话术：约100–200汉字，尽量引用2–3个有来源的数字；数据与解释分开，不承诺必然改善。
5. 分步动作：建议5–6步按时间排序，包含前置核验、动作、观察窗口及停止条件。已做与建议分开；只有原材料或已确认方案支持时才写具体阈值，不能把示例百分比当通用药方。
6. 适用边界：适用条件、不适用情形、至少一个可能推翻原判断的反例，以及是否可迁移到另一客户。
## 术语和因果
SP=商品推广广告，不能泛称搜索广告；ACOS=广告花费占广告销售额比例；CPC=单次点击成本；CVR=订单/点击（注明实际口径）。
广告归因表示按既定窗口记录销售来源，不等于因果证明。价格、库存、促销、季节、Listing、成员与预算变化都可能影响前后结果。
不把AI直接改变转化率作为事实；有日志时说明真实动作及观察，缺对照不宣称增量由AI独立造成。不得把个案收益承诺给所有客户。
## 验收
逐个数字回指输入，重算比例，检查六段完整、客户读得懂、动作可执行且状态真实。新增案例全部标为合成；执行参考 examples/acceptance.md。这里只生成内容，不自动向客户发送。

# 发布与复用边界
本包为实验层公开版，非独立 CSM agent 验证通过版。只提供只读分析与建议；不授予账号、广告修改、发信、审批或对外发布权限。示例全部为人工构造的合成数据，不代表真实客户或效果。
使用者自行提供有权限的 CSV/JSON/报表或只读工具。先查工具与字段是否实际存在，不照抄私有数据库或凭据；字段映射见 references/data-contract.md。
作者与包装维护：土豆。公开包不包含原始客户资料、内部链接、私有脚本或账号配置。
本包与仓库中 Tudou 系列改造草稿并行：保留本技能的独立方法和版本，不覆盖、安装或替换任何现有技能。
