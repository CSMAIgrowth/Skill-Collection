# Case 数据质量与取数范围手册

本手册负责三件事：用 POP 文件快速筛选候选 case、用 SparkX MCP 建立正式事实底座、在输出前拦截日期、范围和名称错误。

## 1. 数据源职责

### POP 文件

POP 下载表只用于快速筛选候选 case，不作为正式 case 的指标来源，也不能替代 SparkX MCP 的托管组、广告活动、投放词、搜索词或广告位数据。

POP 的用途包括：

- 按达标率、表现标签和托管组规模快速缩小候选范围。
- 在多个托管组中先筛选“表现较好/较差”的候选，再决定哪些组值得调用 MCP 深挖。
- 作为候选选择记录，说明为什么从 5 个候选中优先分析 3 个问题组和 2 个正向组。

正式报告中的花费、销售额、订单、ACOS、CPC、CVR、广告活动明细和下钻证据，必须重新从 SparkX MCP 获取。

### SparkX MCP

SparkX MCP 是正式结论的唯一指标来源。正式取数前必须记录：

`Profile｜站点｜托管组 aiGroupId｜当前窗口｜环比窗口｜广告活动范围｜接口/返回层级｜归因口径`

如果 POP 和 MCP 的结果不一致，保留 POP 作为筛选背景，但以 MCP 结果为正式口径，并说明差异原因或待确认点。

## 2. POP 近 N 天筛选逻辑

POP 数据中的 AI 开启前后字段可以用于候选筛选，但必须区分“近 N 天逻辑”和“全周期逻辑”。

### 2.1 近 N 天逻辑

对 `N = 30、60、90、120` 等窗口：

- AI 实际开启并可用天数 >= N：使用完整 N 天的开启后与开启前同长度窗口。
- AI 实际开启并可用天数 < N：使用 N 天范围内实际可用的开启天数 M，做开启后 M 天与开启前 M 天的对比。
- 不足期只用于快速筛选，不能把“实际 M 天前后”写成完整 N 天结论。
- 近 30 天是默认最常用筛选窗口；QBR/HBR/YBR 需要按用户指定的季度、半年度或年度窗口另行判断。

### 2.2 全周期逻辑

只有用户明确要求“全周期 AI 开启前后对比”时，才使用完整 AI 开启期与开启前同长度周期。全周期结果不能替代近 30/60/90/120 天筛选，也不能直接替代当前窗口与紧邻前一等长窗口的正式环比。

### 2.3 候选筛选记录

筛选表建议记录：

`候选托管组｜POP 窗口类型｜实际有效天数｜达标率/标签｜初步筛选结论｜是否调用 MCP｜正式 case 类型`

示例：先用 POP 从 5 个托管组筛出 3 个表现偏弱和 2 个表现较好的候选；调用 MCP 后，再按完整托管组范围、正式环比、设置和日志重新确认，不得直接复制 POP 指标到报告。

## 3. SparkX MCP 正式窗口

正式 case 默认使用当前选定窗口与紧邻前一等长窗口：

- 当前分析窗口 30 天：当前 30 天 vs 紧邻前 30 天。
- 当前分析窗口 14 天：当前 14 天 vs 紧邻前 14 天。
- 当前分析窗口 7 天：当前 7 天 vs 紧邻前 7 天。
- QBR/HBR/YBR：当前季度/半年度/年度 vs 紧邻前一等长周期，除非用户明确指定其他基线。

AI 开启前后只能作为补充分析，必须显式标注为“开启前后对比”，不能混进默认环比列。

## 4. 托管组历史成员范围

托管组正式汇总必须使用分析窗口内生效的广告活动成员，而不是只使用当前时点的成员列表。

每个成员关系至少保留：

`aiGroupId｜campaignId｜完整广告活动名称｜创建/首次投放时间｜加入时间｜AI 实际启用时间｜移出时间｜窗口内生效天数｜当前状态`

如果无法获得历史成员关系：

- 可以使用当前成员列表做初步观察；
- 正式总盘 case 标注“成员范围按当前快照，历史归属待确认”；
- 不得把该结果标为高可信度正式 case。

### 4.1 广告活动级可比性

托管组用于归属 Case，广告活动用于比较效果和归因。必须逐活动先确认「创建/首次投放—加入托管组—AI 启用—暂停/移出」时间线。

| 广告活动状态 | 正确比较方式 | 不允许的写法 |
|---|---|---|
| 当前、对比两个 30 天都稳定纳管 | 活动当前 30 天 vs 紧邻前 30 天，再汇总解释托管组 | 用托管组总盘替代活动表现 |
| 活动中途加入托管组，但加入前已有稳定投放 | 加入后 M 天 vs 加入前 M 天；明确为活动级纳管前后 | 直接套托管组 30 天环比 |
| 活动刚新建、刚开启并加入托管组 | 只展示纳管后 M 天阶段性表现、设置和日志；标注新活动观察 | 将托管组历史表现当作该活动的前期基线，或评价 AI 成败 |
| 组内活动纳管时点不同 | 分「稳定纳管活动」与「新纳管活动」分别展示 | 将混合成员的托管组环比作为单活动因果证据 |

## 5. 数据校验门

正式报告前必须核对：

| 校验项 | 要求 |
|---|---|
| 日期 | 当前和环比窗口同天数，日期首尾、站点时区明确 |
| 范围 | 当前托管组成员、历史成员变化、Profile、广告类型明确 |
| 指标 | MCP 托管组汇总与广告活动明细求和可解释 |
| 公式 | ACOS、ROAS、CPC、CPA 使用汇总后重算，不能平均子行比例 |
| 归因 | 销售额、订单、CVR 的归因窗口一致，平台返回值与自行计算值分开标记 |
| 名称 | 报告中的托管组、广告活动、广告组名称与原始值一致 |
| 日志 | 查询范围、返回数、是否截断、来源、对象、前值、后值和执行状态明确 |

推荐保留差异表：

`指标｜MCP 汇总值｜活动明细求和值｜差异率｜正式采用值｜差异解释`

无法解释的重大差异必须降低证据强度，并停止输出强因果结论。

## 6. 缺失数据降级

| 缺失项 | 允许输出 | 不允许输出 |
|---|---|---|
| 搜索词 | 活动、广告位和投放层观察 | 搜索意图和否词结论 |
| 广告位 | 活动、投放和搜索词观察；广告位效率诊断 | 广告位调价效果结论，或在未核验可编辑入口、权限、当前系数和范围时给出人工广告位固定调幅 |
| 广告活动成员范围 | 局部活动观察 | 托管组完整总盘结论 |
| 托管组设置 | 表现和结构观察 | 设置错配或 AI 未执行结论 |
| 操作日志 | 设置与表现关系 | AI 实际动作归因 |
| MCP 总盘指标 | POP 候选筛选 | 正式 ACOS/ROAS/趋势判断 |

## 7. 交付表格最低要求

每个重点 case 至少有：

1. 表现环比表：当前窗口、紧邻前一等长窗口、差值/增速。
2. 设置-动作-结果表：设置、生效时间、理论动作、实际动作、结果信号、诊断。
3. 影响最大广告活动表：完整名称、花费、花费占比、销售额、订单、ACOS、诊断。
4. 下钻证据表：投放词/搜索词/广告位、时间窗口、筛选范围、关键指标、洞察。
