# 托管组核验公共机制
适用于“托管组三踩一检验”“托管组开启时设置检验”“托管组设置检验”。本文件只约束证据、结果交接与展示；不改变三踩一条件、R1/R2/R3 阈值、各技能的名单范围或只读边界。

## 一、每轮结果快照

每次实际核验建立一个内部结果快照；默认的聊天结论与HTML看板，以及用户另行要求的其他格式和后续归因，均从该快照生成，不在生成不同交付物时重新查询或重新计算。每组至少保存：

| 内容 | 要求 |
| --- | --- |
| 案例关联键 | 客户、Profile/账号、托管组 ID、核验类型及锚点日期/读取时点；组名只作展示，不作唯一键。 |
| 范围 | 店铺、站点、币种、账号时区、采用的自然日解释、窗口起止日期。 |
| 对象映射 | 托管组内部 ID；活动内部 ID 与 Amazon 活动 ID（如两者都存在）；名称与状态。不得混用不同 ID 空间。 |
| 冻结集合与配置 | 本轮采用的活动集合及排除项、一级目标、目标 ACOS、AI 状态；记录取值时间和来源。 |
| 原始与派生数据 | 花费、广告归因销售额、订单、点击和由其重算的 ACOS；不以已舍入比例替代计算基础。 |
| 查询清单 | 数据源、查询范围、读取时间、实际返回账号范围、分页/截断状态、必要的 requestId 或等价追踪标识。 |
| 质量与判断 | 每项规则状态、缺项、采用的假设及最终结果。 |

三种快照不得互相替代：三踩一冻结 D 时点及其前后窗口；开启时设置检验冻结本轮开启时点及其前 14 天；当前设置检验冻结当前读取时点及最近 14 天。它们可由同一案例关联键关联，但不能把其中一份原始数据当成另一份的历史证据。

## 二、执行前数据质量清单

在每条规则计算前逐项检查：授权 Profile 与客户范围、组名到唯一 ID 的映射、成员是否取全、窗口是否完整、币种与百分比单位、基础指标是否可计算、分页是否完成、是否发生截断或已确认查询故障。记录问题影响的具体规则。

- 数据缺失不得补零；仅当该技能已有明确业务口径且查询成功、范围正确、分页完整时，才可按既定口径处理未返回行。
- 某项资料缺失只阻断依赖它的规则；可独立判断的规则继续输出，不能把整组一概写为合格、不合格或无法判断。
- `get_entity_metadata` 一类当前配置读取只能证明当前状态，不能代替历史设置或历史成员；历史结论须有快照、设置日志或操作日志。无从还原时明确写无法判断。
- 操作日志存在分页/截断和时区风险。单店与多店日志不得混在同一时间线；时间展示必须标明店铺当地时间或 UTC。未查到日志不等于没有操作。

## 三、规则、解释与结果三层

按顺序输出：

1. **规则结果**：仅用该技能已确认的机械条件，状态使用“合格/不合格”或“命中待复核/未命中/无法判断”。
2. **证据与质量说明**：展示计算基础、来源及会影响判断的缺项，不把观察位置写成原因。
3. **解释与建议**：只说明可能影响、待确认条件和调整方向。不得把风险待复核写成设置错误、效果因果或算法责任。

## 四、交接合同与后续写入

| 上游 | 交接给下游的最小内容 | 不得越过的边界 |
| --- | --- | --- |
| 三踩一检验 | 不合格组、D、D 时成员集合、前后窗口、期末目标口径、三项结果、缺项、快照标识 | 不解释原因，不判算法责任。 |
| 开启时设置检验 | 本轮开启事件、开启时成员、开启前 14 天、R1/R2/R3、历史还原来源、缺项、快照标识 | 不把当前设置倒灌为历史事实，不直接生成修改指令。 |
| 当前设置检验 | 当前读取时点、当前成员和配置、最近 14 天、R1/R2/R3、风险与条件性方向、快照标识 | 不倒推历史，不判效果或算法责任。 |
| 后续归因/实施 | 读取以上快照后，再补人工操作、促销、库存、Listing、AI 执行记录或获授权的修改 | 不把筛选或风险线索直接当作算法缺陷或写入授权。 |

任何实际调整另建“调整实施交接单”：对象及 ID、当前值、建议值或方向、依据、可能影响、授权状态、写入结果和回读结果。写入前先展示解析后的对象和完整范围；写后重新读取目标组及活动关系。接口成功只代表技术状态，未回读不得称已生效；尚未实施时交接单状态为“未授权”或“待确认”。

## 五、内部 HTML 看板格式

默认交付 HTML 看板时，优先保留本轮用户已确认的布局。当前两页展示参考为[站点筛选设置卡片精简版（移植依赖说明）](外部依赖与移植说明.md)；[具体风险标签版（移植依赖说明）](外部依赖与移植说明.md)仅作原始设置卡片参考。二者都是静态展示参考，不是实时数据源；历史版不覆盖。

- 生成独立、可离线打开、响应式的静态 HTML；使用轻量浅/深色适配、顶部标题栏、范围/快照说明和无外部数据请求的嵌入式内容。
- 顶部先展示标题、客户/店铺范围、核验窗口、读取时间和“静态快照，非实时监控”标识。
- 首屏按本轮确认的总览展示数量、占比与分母，避免同一组数字反复出现在结论、指标卡和流程图中。当前两页版不再叠加四张汇总卡和“核验流程”板块；其他交付按用户当次布局要求处理。
- 总览设置检验摘要统一采用：“对N个不合格组执行托管组设置检验，R组存在设置风险；其余P组未命中三类风险，进入高花费活动检验。”N、R、P从同一冻结快照生成，不固定使用36、31、5；只有其余组均完成三类规则且未命中时才使用此句。有无法判断时另行说明，不把未知当作通过；摘要措辞不改变实际历史时点或检验口径。
- 三踩一与开启时设置联动展示时，已保留的漏斗/金字塔标注为筛选链路，不能暗示因果；不因复用旧模板重新添加用户已删除的重复板块。
- 托管组明细使用可折叠卡片：组名、店铺、ID、结果状态；三踩一显示前后订单、前后 ACOS、采用目标；开启时/当前设置显示 R1-R3 规则卡、条件、数据证据和质量说明。只展示本轮快照中的内容。
- 单独保留“口径与数据来源”区域：快照标识、窗口、成员/目标取值规则、数据源、币种、缺项处理和非因果声明。不要把原始日志全文或敏感凭证写入 HTML。
- 内部 HTML 可以展示数值、ID 和规则证据；对客 HTML 仅在用户明确要求时另建，沿用当前设置检验的对客信息边界，不以隐藏列、脚本或折叠内容夹带内部数据。

## 六、纠错记录、回归自检与周期复盘

交付标记按[项目成果标签规则（移植依赖说明）](外部依赖与移植说明.md)执行：成果版本、实际生成时间或“原生成时间未记录＋补标时间”、明确时区、数据读取/截至时间分开显示；采用的Skill版本不能替代成果版本，快照时间不能替代生成时间。共享包使用同一份标签并重算manifest校验值。交付前执行标签覆盖检查，不以此关闭浏览器待验证项。

用户指出错误时，在修复同轮更新[托管组核验错误样本与自检](托管组核验错误样本与自检.md)，三个技能共享一份记录。每次生成或修改 HTML 前读取与当前改动有关的样本；交付前运行相应静态检查，并对筛选、排序、卡片展开执行浏览器检查。完整操作矩阵、误差容限和证据状态见该文件。

静态自检入口：`node scripts/check-managed-group-html.mjs --input <本轮artifact.json>`。它只能验证结构和已知样式风险，不能代替真实点击、对比度或坐标验证。浏览器不可用时记录受影响项目及具体原因，交付表述为“已修改，静态检查通过，浏览器待验证”。周期复盘读取错误样本与可访问的新反馈，归并重复根因、检查修复是否复发及是否还欠行为验证；不得把总结任务变成刷新广告数据或修改广告配置的任务。
