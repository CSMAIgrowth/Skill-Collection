# 店铺广告复盘与重点父 ASIN

技能版本 v1.0.0 · 仓库交付版 · 可公开复跑的示例见[案例 01](examples/case-01/task.md)。

交付回答两件事：客户这两期广告投入怎么变，ACOS 为什么变；哪些父 ASIN 对这次变化影响较大，客户下一步该查什么。到优先名单与排查方向为止。用户只要某张表或其中一层时，按当次范围交付。

1. 确认客户、分析窗口、店铺范围和币种。只给本期时，上期默认为紧邻等长周期，保留用户明示日期。实时查询先验证该客户独立连接的当前授权；复用冻结材料时核对其身份、窗口和覆盖。读取[取数与筛选口径](references/data-method.md)。
2. 用两期分子分母复算账户大盘和效率。先找增减投集中处与 ACOS 变化，再按国家站点 → 店铺 → 品线 → 投放类型下钻。必要时用点击占比区分流量流向和组内效率变化。计算和报告分别保留活动报表、推广商品报表、搜索词报表的覆盖范围。
3. 将推广商品按站点、店铺和真实父 ASIN 聚合。对同口径且可计算 ACOS 的父体，以本期花费减去「本期广告销售额 × 上期 ACOS」筛选和排序。每个入选项给出站点、店铺、品线、两期指标、入选原因和下一步重点。输出名单时顺序和筛选口径一致。
4. 读取[界面和交付](references/delivery.md)，交付一份沿用确认成品结构的独立 HTML。用 [render_report.py](scripts/render_report.py) 渲染已经核验的汇总数据。验证页面切换、筛选总计、卡片折叠和窄屏表现。

进一步诊断具体商品、检查操作责任、调整广告或对外发送，均由对应任务单独发起。
