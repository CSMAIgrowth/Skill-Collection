# SparkX 客户月度复盘（MCP 版）

## 目标与适用边界

**解决的问题**：用 CSM 自己账号授权的 SparkX AI MCP 数据，把一个客户一个周期的广告经营、AI 托管使用和效果复盘清楚，给出客户能执行的下期动作。

**适用**：月度复盘、双周复盘、MBR 准备、"AI 到底有没有用"的周期核查。

**不适用**：
- 年度复盘、续约前全年价值汇报 → 用 `xnurta-ybr`。
- 侧重系统功能采纳、账号使用情况的 SparkX 使用报告 → 用 `xnurta-csm-review`。
- 只查单个指标 → 直接用官方查询 Skill。
- 本技能不修改广告和托管组。SparkX AI MCP 有写权限，但复盘只读；客户确认要执行某条建议时，另行使用官方写操作 Skill，并按它的确认流程走。

## 输入

| 输入 | 是否必填 | 默认 / 来源 |
|---|---|---|
| 客户与店铺范围 | 必填 | 用 `get_user_authorized_context` 列出已授权店铺，请用户确认；未指定时只在能确认同一客户的已授权店铺内取数；跨客户先问范围 |
| 本期起止日期 | 必填 | 用户未给时，默认上一个完整自然月 |
| 对比期 | 可选 | 默认等长的上一期；自然月天数不同时补日均 |
| 广告类型 | 可选 | 默认 SP 为主体，SB / SD 单列，不含 DSP |
| 读者 | 可选 | 默认客户运营负责人；给老板看时第一章更短 |
| 客户目标、毛利、库存、促销计划 | 可选 | 用户提供；缺失时只给有条件的建议 |
| 合同、服务记录、登录活跃 | 可选 | MCP 取不到，由用户提供，否则标"未提供" |

不能猜测：客户目标、负责人、截止日、当年活动日历、毛利和库存。缺少会改变结论的输入时最多问 3 个问题，同时先做不依赖答案的部分。

## 依赖与权限

- **输入方式**：已授权导出或实时SparkX AI MCP。查询方法全部内置，见 references/query-guide.md。
- **报告标准已内置**：references/report-standard.md、report-blueprint.md、quality-check.md。
- **可选**：卖家精灵、SIF 等市场数据工具（需要 CSM 自己的授权），只用于第三章市场背景。
- **权限**：只读查询 + 生成报告文件。不写广告系统、不发给客户、不扩大文档分享范围。MCP 返回的数据只用于当前客户的报告，不放进其他客户的材料。

## 执行方法

### 1. 定范围和口径
1. 调 `get_user_authorized_context`，确认店铺、站点、币种（多店铺时 MCP 统一换算为 USD）。
2. 确认本期 / 对比期。单次查询不超过 90 天，超过就分段；数据约 T+2，结束日不晚于前天，最后 2–3 天标注"归因未完全回流"。
3. 读 [references/04-SparkX-MCP取数对照.md](references/04-SparkX-MCP取数对照.md)，按里面的对照表规划要调哪些查询。

### 2. 取数（全部只读）
按顺序做，每一步的结果落到本次任务的独立工作目录：
1. **大盘**：`get_ads_perf`，factEntity=`campaign`，按广告类型分开，两期各取 `Spend` `Sales` `Conversions` `Units` `Clicks` `Impressions` `AISpend` `AISales`。
2. **逐日**：campaign 实体、同样的指标，加 `date` 维度，用来看 AI 花费占比的波动和突变。
3. **分店铺、分托管组**：campaign 实体加店铺维度和 `aiGroup` 维度（托管目标、目标 ACOS）。
4. **店铺经营**：factEntity=`asin`，取 `TotalSalesAmount` `TACOS` `Sessions` `UnitSessionPercentage` `BuyBoxPercentage`。只在 asin 实体上取，不和广告实体混合。
5. **同 ASIN 比较**：factEntity=`productAd` 按"活动 × 日 × ASIN"取，再用第 2 步的"活动 × 日"AI 花费标记 AI 侧。
6. **托管组配置**：`get_entity_metadata`，entity=`aiGroup`：在跑状态、托管目标、目标 ACOS、人格、行动空间开关。配置是当天快照。
7. **操作日志**：`get_operation_log`，分 AI 和人工，取调价、调预算、启停、否词、托管组设置变更。`truncated=true` 时拆日期重查，或者标"部分记录"。
8. **重点 Case 下钻**（只对选中的托管组或活动）：`target`、`searchTerm`、`placement` 实体，取近 7 / 14 / 30 天。

单次取数失败时，按官方 Skill 的错误说明修正参数后重试，最多 2 次；仍失败就记录缺口（带 `requestId`），继续做不依赖它的部分。

### 3. 关键口径
- **AI 归属**：用 MCP 的 `AISpend` / `AISales`（活动 × 日粒度）。人工侧 = 总量 − AI 侧。不要用"整期出现过 AI 花费的活动全部算 AI"。
- **比率重算**：ACOS、CPC、CVR、客单价、TACOS 都用原始分子分母汇总后重算，不平均子项。MCP 返回的百分比已乘 100。
- **同 ASIN 比较**：只纳入两侧都有投放的 ASIN，写明纳入门槛、样本数、花费覆盖率；整体结果和逐 ASIN 结果都给，不利样本也保留。这是观察性比较，不是随机实验。
- **ACOS 三因子**：同口径下 `ACOS新/ACOS旧 = (CPC新/CPC旧) × (CVR旧/CVR新) × (客单价旧/客单价新)`，用未舍入数据验算，误差 < 0.5%。闭合不了就先查口径，不下结论。
- **配置与时间**：近期才开启的行动空间，不能用整月结果评价；配置快照不能当历史证据，要看操作日志里的变更时间。

### 4. 写报告（五章）
读 本包 `references/report-standard.md` 的报告蓝图。本技能的分析维度按下表放进五章：

| 正文章节 | 放什么 | 参考 |
|---|---|---|
| 一、老板一页摘要 | 本期经营总览、3–5 条关键发现、机会 / 风险 / 下一步 | [01](references/01-分析维度详解.md) 第一节 |
| 二、分店 / AI 使用与同款比较 | AI 花费占比、AI 动作（日志计数）、AI 与人工整体和同 ASIN 比较、四维汇总中有决策价值的维度 | [01](references/01-分析维度详解.md) 二至四节、[02](references/02-四维汇总写法.md) |
| 三、市场与旺季 | 有来源和日期的品类 / 关键词信号、账户自身的历史旺季、当年准备计划；没有外部数据就写自身历史，并标"市场数据未取得" | — |
| 四、分店具体诊断 | 按实际证据选择重点 Case（4–6个仅为篇幅建议，不凑数）：现状、证据、已确认原因与待验证解释、配置与日志、动作、观察节奏 | [03](references/03-单Case诊断法.md) |
| 五、行动表 | 优先级、对象、动作与前提、负责人（角色）、建议日期、验收和停止条件 | — |

文末附"数据说明"：每张表的 MCP 工具与查询条件、取数时间、口径、样本覆盖、缺口和限制。

### 5. 交付前验收
按 本包 `references/report-standard.md` 的验收清单自查；图表必须真实生成并嵌入。写入在线文档后回读，检查章节、关键数字、图表和行动表是否完整。

## 输出

- 一份五章结构的复盘报告（在线文档或 Markdown），含真实图表、行动表、数据说明。
- 工作目录里保留每次查询的参数和原始返回，方便复核。
- 不自动发给客户，不自动改广告。

## 验收标准

- 大盘数字与 SparkX 前台同口径（同店铺、同日期、同广告类型）对得上；对不上时在数据说明里解释原因。
- AI 侧 + 人工侧 = 全量；同 ASIN 样本的纳入规则、样本数、覆盖率写清。
- 三因子分解闭合，误差 < 0.5%。
- 每个重点 Case 都有托管组配置和操作日志证据；缺日志时写"未取得"，不推断"AI 没行动"。
- 行动表每条都有对象、前提、负责人（角色）、日期或启动条件、验收指标。
- **需要业务确认的**：目标 ACOS 调整幅度、预算变化、库存和促销前提、负责人和日期。

## 异常与已知限制

- **MCP不可用**：停止实时取数；若用户有授权导出，按本包数据契约继续。无数据时询问必要输入，不拿样例代替。
- **某个店铺未授权**：整次查询会失败；只查已授权店铺，在报告范围里写明缺哪些。
- **日志被截断**：拆日期段重查；仍截断就标"部分记录"，不推算全量。
- **取不到的数据**：合同、登录天数、跨客户大盘、市场搜索量、否词拦截金额。按对照表第 4 节处理，写明缺口，不编造。
- **样本小**：AI 侧或某个广告位花费很小时，只作为线索，不作为结论。
- **限制**：同 ASIN 比较只能把 AI 标签挂到"活动 × 日"，挂不到关键词层；托管组配置只有当前快照。

## 测试样例

- **自然提问**：「帮我给这个客户做 9 月的月度复盘，对比 8 月」。
  - **预期**：确认已授权店铺和日期，按第 2 节取数，产出五章报告；AI 与人工比较有整体和同 ASIN 两套，并写明样本和限制。
- **自然提问**：「这个店上个月 ACOS 涨了，帮我复盘一下原因」。
  - **预期**：完成三因子分解，指出主因（CPC / CVR / 客单价），结合配置和日志给 Case 诊断与动作。
- **不应触发**：「上周花费多少」只需要直接查询，不需要出复盘报告。
- **测试状态**：来源版本的MCP真实客户路径未验证；本组合版的合成执行回执随交付包提供，不能替代真实授权、接口及前台对账。
