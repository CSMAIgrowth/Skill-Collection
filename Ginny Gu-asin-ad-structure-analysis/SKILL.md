# 单个 ASIN 广告结构分析

把运营判断落成可复查的诊断：这个商品的钱花在哪里，哪些入口在贡献订单，成本高是否值得，哪里可增量、哪里应收缩，以及怎样验证建议。先整体、再结构、后具体活动和词，避免只给指标排名或通用广告知识。

方法来自一场运营讨论，会议要点与新增执行设计见 [references/method-origin.md](references/method-origin.md)。需要解释来源时才读取；不将会议中某家店铺的状态、目标或建议套给其他客户。

## 触发和输入

用户指定一个 ASIN，并要求诊断投放结构、增长入口或成本效率时使用。可直接说“分析这个 ASIN 的广告结构，哪里能增量，哪里要缩量”。缺少 ASIN 或站点/店铺身份且无法唯一解析时，先问清身份；不要挑一个客户或商品代替用户。

确认或从当前上下文沿用：客户、专属数据连接/文件、Profile、站点、子 ASIN、周期、目标、预算与库存约束。父 ASIN 需先确认分析是否覆盖全部子体，不能拿某个子体代替父体。目标至少明确是降低 CPA、保持转化下增订单、改善利润还是探索新流量；“增量”不够时，先提出可验证目标供用户补充。

周期未指定时，建议最近 14 个已完成自然日，等长前 14 日作背景；按站点时区标日期，近期 T+2 数据与广告归因未成熟要说明。样本小可扩至 28/30 天，但跨测试、大促、价格或库存变化时分阶段，不用更长均值掩盖变化。纪要的 14 天是起始观察窗口，不是所有产品的固定标准。

目标 CPA/ACOS 未提供时，以自身基线做相对效率诊断，标为“盈利阈值待确认”。不得凭行业经验编造毛利。若毛利口径包含退货、折扣、费用，则用同口径推算盈亏 CPA/ACOS；广告订单并非总订单，单个 ASIN 的总销售也不等于广告归因销售。

## 数据路径与授权

- 用户已授权当前客户 MCP 取数时，先用客户专属连接的 `get_user_authorized_context` 校验身份及 tenant/Profile，再取“返回授权 ∩ 当前客户 allowlist”。范围缺失或冲突时停止业务查询，说明缺口。不因 skill 触发而自动取得其他客户或连接的访问权限。
- 用户只要求整理附件或创建 skill 时，只用提供素材。没有取数授权时可以产出数据需求和待验证判断，不调用客户 MCP。
- SparkX 取数前读取已安装的 `sparkx-query-ads-performance`、`sparkx-query-entity-metadata` 的 SKILL.md，并按所需实体查其字段参考、指标适用性与平台规则。仅在调查调整历史时读取 `sparkx-query-operation-log`；评估 AI 动作时追加 `sparkx-ai-action-review`。这些是执行 SparkX 查询的依赖；缺失则说明并改用已给数据或提供取数需求，不猜参数。
- 所有查询只读；建议不等于广告改动授权。用户另行要求执行时转交适用编辑 skill 和其确认流程。

## 1. 建立 ASIN 与广告的关系，锁定证据范围

先从 `get_entity_metadata(entity='productAd')` 用 plain camelCase 的 `asin` 过滤目标商品，完整分页，收集 Profile、SKU、活动、广告组、广告类型和商品状态。同时从该商品的本期/上期 productAd 表现补充历史有投放的对象：当前商品关系可能漏掉已删除、迁移或停投的结构，不能把当前快照当历史全貌。

在相关广告组内查全部商品，识别单商品与多商品共用；当前单商品快照不能证明整个历史窗口也只投一个商品。建立内部关系清单：Profile → ASIN/SKU → 活动 → 广告组 → 单/多商品 → 类型 → 本期/上期是否有表现。ASIN 重复 SKU 不能按 ASIN 粗暴去重掉有效商品广告行。

**两套 ID 必须转换**：metadata 的 `campaignId`/`adGroupId` 是平台内部 ID；performance 的同名层级 ID 是 Amazon ID。从 metadata 的广告组内部 ID 再查 `entity='adGroup'` 得到 `amazonAdGroupId`，之后才能用 Amazon ID 限定表现查询的 `p.adGroupId_`；活动同理映射 `amazonCampaignId`。按 Profile + 对象类型保存映射，不用数字外观判断 ID，也不因错误 ID 导致空结果就断言无流量。操作日志所需 ID 空间另按该工具文档核实。

**三类证据分开标注**：

| 证据范围 | 可以回答 | 不能推出 |
|---|---|---|
| ASIN 专属商品广告表现 | 本商品广告花费、归因销售/订单、活动分布 | 具体词 × 本商品的表现 |
| 含该 ASIN 的广告组/活动表现 | 相关投放框架、定向、搜索词、位置、受众 | 多商品共用对象的全部业绩由该 ASIN 贡献 |
| 当前配置/运营补充 | 当前预算、出价、否词、商品和测试意图 | 历史配置、自然排名或广告因果效果 |

## 2. 先看总盘，再重建投放结构

**ASIN 总盘**：商品广告用 `factEntity='productAd'`，过滤 `productAd.asin_`，按 Profile、SKU/商品广告 ID 及父级活动/广告组汇总基础指标：Impressions、Clicks、Spend、Sales、Conversions。保留活动名称便于运营定位。不要在 `factEntity='adGroup'` 上加 productAd/asin 维度：会把整组指标复制给每个商品。仅当需业务总销售/TACOS，单独用 `factEntity='asin'` 并核实 Seller/Vendor 指标；不把业务指标与广告层级联表。

**结构明细**：target 与 searchTerm 保持自己的 factEntity，只按映射后的相关广告组 Amazon ID 限定范围，不能添加商品维度伪造“词 × ASIN”数据。target 按工具契约分别请求 keyword/product/auto；searchTerm 不传 `queryType='auto'`，自动搜索词应在完整搜索词结果中按真实 matchType 识别。多商品组的结果只能叫“包含该 ASIN 的广告组表现”。即使是单商品组，也说明历史商品关系是否得到验证。

SP 至少检查：精准、词组、广泛、自动、商品定向。商品定向可有证据时再拆自身品牌/竞品/类目，自动可再拆紧密/宽泛/替代/关联。未知产品归属保留“待确认”，不要凭目标名称猜自有或竞品。不要把自动替代/关联入口算作人工商品定向再重复加总。

**两张结构视图**：

- 渠道层：SP/SB/SD 的本 ASIN 商品广告花费、销售/订单占比与效率；不能归属的 SB 多商品素材或品牌/店铺落地流量单列相关活动，不强行塞入 ASIN 总计。
- SP 定向层：按相关广告组的 target/searchTerm 数据拆入口；注明覆盖范围和分母。若无法获得 ASIN 专属定向拆分，渠道表与 SP 定向表使用不同分母并明确说明，不能混在一个“ASIN占比”表里。

完整分页至 `hasNextPage=false`，校验有效 Profile。按同一实体、周期、范围对账加总；并列维度可各自分析，不能把渠道、位置、受众、匹配类型几张表的花费相加。搜索词数据不一定覆盖全部广告花费，给出覆盖差额而非硬凑 100%。详见 [references/diagnosis-and-output.md](references/diagnosis-and-output.md)。

## 3. 用 CPC、CVR、CPA 联合判断增量与缩量

先加总基础量，再计算：CPC=Spend/Clicks；CVR=Conversions/Clicks；CPA=Spend/Conversions；ACOS=Spend/Sales。CVR、ACOS 输出百分比。广告归因订单数不等于销量。零分母写“无订单/无销售/不可计算”，不写 0% 或无穷大。对返还的已缩放百分比不得二次乘 100。

当定义一致时 CPA=CPC/CVR（CVR 用小数），可辅助解释成本：

- CPC 高、CVR 高且 CPA 达标：可能值得保留或测试扩量；不能单因 CPC 贵而降价。
- CPC 高、CVR 无补偿且 CPA 差：定位拖累活动/目标；优先检查相关性、抢位、出价与样本成熟度，再提出收缩候选。
- 效率好、花费小：是扩量候选，先查可售库存、目标与实际预算约束。没有预算耗尽或流量潜力证据时，不说“加预算一定增单”。
- 广泛/自动份额少或未投：先查过去失败、主动缩量及测试目的。只作为待测试入口，不规定广泛预算必须大于自动或精准占比必须达到某数。
- 总体弱但部分成熟活动好：分开成熟存量与新品/新词探索，避免因平均值掐断已有增量；新对象无历史比较写“新投放”。

结构缺口分成“确认存在且有效率证据”“有理由小范围测试”“数据不足待验证”。缺渠道并不自动等于问题。投入份额高于订单份额说明 CPA 相对更高；高于销售份额说明 ACOS 相对更高，分别说清，不混用。

## 4. 深挖入口集中度与 SB/SD/受众

按已验证范围把搜索词去重汇总，再计算 Top1/Top2/Top5 的订单、销售和花费占比；ASIN 格式的商品页匹配目标与文字搜索词分开。给出分母、未覆盖量和每日日均订单。少数词贡献集中说明依赖风险，不能直接证明自然位不稳或销量将下跌。

找“稳定有效词”“有成交但覆盖不足词”“高点击无单/效率差词”和“尚缺证据的机会”。样本门槛依据目标CPA、成本上限与归因成熟度说明，不能固定若干点击就否词；词重叠也不能证明自我竞价。ABA、自然排名、竞品流量来自用户提供或另行授权的数据源，缺失就保留待验证；不从广告订单推自然排名。

SB：对齐当前与历史同口径活动，先看成本与转化，再检查投放目标、位置与用户提供的素材/落地页。不能因 SP 好而断言 Listing 完全无问题。没有已支持的素材类型字段或人工素材映射时，不把全部 SB 当 SBV。CPC/vCPM 是有条件测试方向，先查站点/格式资格与可用数据；浏览归因、点击归因指标分开，不直接拿两种计费的 CPA 做因果比较。

SD：检查当前缺投是否因为历史试验失败；重定向/受众/商品等入口按实际配置理解。存在回访流量机会仅代表测试假设，不保证 SD 一定有效；不因其他客户成功建议全量开投。

受众：检查实际绑定、人群定义、加价和样本；支持 `campaignAudience` 时先读其专属工具契约，用其直接受众报告。绑定了受众的活动总表现不能当成人群专属表现，受众与非受众需同定义比较。绑定状态看 `audienceId`，不靠加价是否为0。缺少 AMC 受众粒度数据时，仅交付测试设计和缺口，不自动建包或宣称能复制其他产品的人群。

## 5. 交付判断与可验证行动

用用户语言，先回答“问题在哪、为什么、先改什么”，再给必要表格。每条主结论带对象、数值、时期、证据范围；把已确认事实、原因假设、待确认项分开。不堆通用知识，不把同步发生的调整当因果。

最低交付：ASIN总盘及等长基线、两层结构（不可用部分说明）、有效与拖累对象、搜索入口集中度、SB/SD/受众判断、行动及取数缺口。输出格式与具体决策规则见 [references/diagnosis-and-output.md](references/diagnosis-and-output.md)，按数据规模取舍，不要求固定章节数。

建议必须指明活动/广告组/目标、依据、改变什么、何时执行、负责人、预算/成本上限、观察窗口、成功条件、止损/回滚条件。通常先小范围做7–14天观察，注明归因成熟后再评价；低量延长，高风险提前检查。金额/百分比采用用户约束或标成待定，不编造“精确最优出价”。

若复盘实施效果，用相同范围等长前后数据并列测试/未变对象，标注促销、库存、价格、素材和人工操作。前后比较提供方向性证据；无有效对照时不称为广告或AI的因果收益。skill 不自动创建监控、定时任务或执行广告更改。
