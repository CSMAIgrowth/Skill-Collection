# 诊断与交付细节

## 取数和对账

每个数据集登记客户/Profile、站点/币种、日期/时区、factEntity、筛选条件、ID空间、分页状态、广告类型和归因口径。保存返回覆盖量及未归属行，避免空结果被当0。

productAd明细按 Profile + Amazon广告ID（再加日期，如逐日）识别行，聚合至活动/ASIN时先加总；不能在不同粒度表之间简单拼接。相同ASIN不同SKU、活动与广告ID可各有有效花费。

target和searchTerm是两种视图，不可相加。匹配类型按实际枚举归类；target.keyword的exact/phrase/broad与自动queryHighRelMatches等区分。搜索词matchType可能大小写与target不同，读取实际值。当前配置的“未投”、本期“零花费”、历史“停投”是不同状态。

共享广告组中的结构、集中度、活动日志始终说明覆盖其他商品。只有同期关系得到充分验证为单商品时才可以强化关联解释；即使单商品，也不能伪造不存在的词×商品原生归因。历史关系缺失不做精确分摊。

对于无法直接归属的SB商品集、品牌店铺流量，展示“相关SB活动表现，非ASIN专属”；没有映射不能说目标ASIN没有SB支持。位置与受众维度也沿用其本身统计对象。百分比每张表明确分母；同一结构不可同时把“关键词合计”和其精准/词组/广泛子项再计入总额。

默认单Profile本币；多个Profile按站点分别分析。用户要合并时，核实工具真实换算口径及汇率信息，货币不同且没有可复核转换则不合计；metadata配置本币不能与表现折算金额相加。

## 典型判断

| 观察 | 当前可下判断 | 下一步需要的证据 |
|---|---|---|
| 精准CPA稳定达标，订单集中在少数活动 | 存量扩量候选，先保护有效对象 | 是否实际受预算约束、库存、流量空间 |
| 商品定向花费大、CPC贵、CPA差 | 该入口相对效率弱 | 拆高效目标与新探索、相关性/抢位/调整记录 |
| 广泛/自动占比低 | 探索入口较小或主动收缩 | 失败试验、否词、现有有效词及亏损限额 |
| Top2词订单集中 | 已覆盖搜索流量依赖少数入口 | 自然排名、词量、全搜索覆盖度；无数据则待查 |
| SP强而SB弱 | 同商品在不同渠道效率不同 | 素材、落地页、位置、竞价及受众，不直接归因竞争 |
| 绑定受众活动好 | 有受众配置的活动表现好 | 受众专属曝光/点击/订单及未命中流量 |
| 无SD表现 | 可能未投、停投或数据缺口 | 关系映射、历史试验、库存和业务目标 |

扩量理由不能仅是ACOS低或份额少；需要目标匹配、样本成熟和可承受成本。探索预算份额按本商品目标与历史测试决定，无固定“健康结构比例”。不用其他客户的表现作为本客户效果证据。

## 建议的对客呈现

开头用一段话回答：当前有效核心是什么、主要拖累在哪、第一步建议做什么、什么仍待确认。接着写清店铺/站点/ASIN、周期、币种、归因与数据覆盖。

可使用以下普通Markdown表格，列不必全部保留，避免堆叠大表：

- 总盘：时期、花费、广告销售/订单、CPC、CVR、CPA、ACOS；零基数不算增长率。
- ASIN渠道：广告类型、花费及占比、订单及占比、CPA、ACOS、证据范围。
- SP入口：定向类别、花费、订单、CPC、CVR、CPA、趋势/阶段、覆盖范围。
- 核心对象：活动/广告组/词或商品目标、表现、已确认事实、原因假设、建议。

搜索集中度同时列文字搜索词与商品页目标，不把前者的Top2贡献当作全部ASIN订单贡献。SB/SD/受众若缺数据，说明“缺什么、影响什么判断、下一步怎么验证”，保留其他完整结论。

行动表字段：对象、建议/具体变更、依据、执行条件与负责人、测试预算/成本上限、观察期、成功标准、复查与回滚条件。参数缺失写待确认；执行前让运营核定，不填写未经验证的预算或出价。

若需调查历史变化，按正确活动/广告组ID取日志、检查truncated并拆分非重叠窗口；日志属于相关活动/广告组，不是ASIN专属。操作前后做同对象等长窗口，当前快照只说明现在。无日志时原因只能是假设。

## 可直接给运营的提问示例

“请使用 $asin-ad-structure-analysis 分析【客户/店铺/站点】的【子ASIN】，周期【起止日期】，对比等长前期。目标是在CVR不低于【阈值】、CPA不超过【本币金额】的条件下增加广告订单。数据源是【已授权的客户专属MCP或附件】。先确认ASIN与活动/广告组关系，分开ASIN专属数据与共用广告组数据；分析SP入口、搜索集中度、SB、SD和受众，给出可小范围验证的增量/缩量建议、上限、成功标准和回滚条件。本次只读分析。”
