# 年度业务复盘 YBR（MCP 版）

## 目标与适用边界

**解决的问题**：用一份老板能看懂的报告讲清楚一年里生意怎么变、系统和 AI 起了什么作用、下一年怎么做。规模在收缩就如实写，不粉饰。

**适用**：年度复盘、续约前全年价值汇报、按 YBR 模板整理客户全年数据。

**不适用**：
- 单月或双周复盘 → 用 `xnurta-monthly-review`。
- 系统功能采纳为主的使用报告 → 用 `xnurta-csm-review`。
- 报价、套餐、续约条款 → 由商务按合同确定，本报告不写价格。
- 本技能只读，不改广告或托管组。

## 和月度复盘的区别

| 维度 | YBR | 月度复盘 |
|---|---|---|
| 周期 | 12 个完整月 | 一个月或双周 |
| 受众 | 客户老板 / 续约决策 | 运营团队 |
| 落点 | 一年的系统价值 + AI 覆盖 + 下一年路线图 | 单期问题诊断 + 下期动作 |
| 对比轴 | 四季度趋势 + 首尾季度对比 | 本期 vs 上期 |

## 输入

| 输入 | 是否必填 | 默认 / 来源 |
|---|---|---|
| 客户与店铺范围 | 必填 | `get_user_authorized_context` 列出已授权店铺，请用户确认 |
| 复盘窗口 | 必填 | 默认最近 12 个完整自然月；如需与合同期对齐，由用户给出合同起止日 |
| 合同信息、套餐 | 可选 | 用户提供；不提供就不写合同相关内容 |
| 系统使用数据（登录、功能、通知、Insight Agent） | 可选 | MCP 取不到；用户提供前台数据，否则写"未取得" |
| 毛利、库存、下一年目标 | 可选 | 用户提供；路线图目标值注明"需运营结合利润 / 库存 / 推广计划确认" |
| 客户对"达标"的约定口径 | 可选 | 默认三踩二；客户服务计划里另有约定时以约定为准，并同时附三踩二 |

## 依赖与权限

- **必需**：SparkX AI MCP + 官方三个查询 Skill（https://github.com/SparkXAI/SparkXAI-MCP，按 2026-10-22 manifest release v1.3.4 编写；参数和字段以官方 Skill 为准）。
- **配套技能**：`xnurta-report-standard`（同批提交），用于写作底线和交付验收。
- **权限**：只读查询 + 生成报告文件。不写广告系统、不对外发送、不扩大文档权限。

## 执行方法

### 0. 开工三件事
1. **定店铺**：调 `get_user_authorized_context`，确认纳入哪些店铺。客户中途解绑或新授权的店铺会造成月度断层，要拆出"全年都在的店铺"做同口径趋势。
2. **定窗口**：MCP 单次最多 90 天，最多回溯 15 个月。12 个月要分 5 段左右取，按月合并。
3. **定能否同比**：同比需要 24 个月数据，超出 MCP 的 15 个月回溯范围，**默认不做同比**，改用四季度趋势 + 首尾季度对比，并在数据说明里写原因。账户在复盘期内才接入的，也不能做同比。

### 1. 取数（全部只读，按 [references/02-SparkX-MCP取数对照.md](references/02-SparkX-MCP取数对照.md)）
1. **月度大盘**：`get_ads_perf` campaign 实体，按月聚合，SP / SB / SD 分开，取 `Spend` `Sales` `Conversions` `Units` `Clicks` `Impressions` `AISpend` `AISales`。
2. **店铺经营**：asin 实体按月取 `TotalSalesAmount` `TACOS` `OrganicSales` `Sessions`，算广告归因销售占比和非广告归因销售。
3. **AI 侧与人工侧**：campaign 实体按"活动 × 月"取 AI 和总量；人工侧 = 总量 − AI 侧。
4. **同 ASIN 比较**：productAd 实体按"活动 × 日 × ASIN"取，用活动 × 日的 AI 花费标记 AI 侧，只纳入两侧都有投放、各自花费达到门槛的 ASIN。大账户按店铺分批取。
5. **托管组**：`get_entity_metadata` aiGroup：当前在跑 / 已关、托管目标、目标 ACOS、行动空间开关、建组人。
6. **托管组达标**：首末季度（或最近两期）按 aiGroup 维度取花费和销售，算三踩二（见第 3 节）。
7. **维度切分**：站点、店铺、广告位（placement 实体，首季 vs 末季）、商品（productAd 与 asin 实体，首季 vs 末季 Top ASIN）。
8. **AI 动作**：`get_operation_log` 按 90 天分段统计 AI 的否定、加词 / 收割、调价、调预算次数；能回溯的月份以实际返回为准。

单次失败按官方 Skill 修正后最多重试 2 次；仍失败记录缺口和 `requestId`，继续其他部分。

### 2. 三条铁律
- **铁律一：AI 按实际托管时段归属。** 用 MCP 的 `AISpend` / `AISales`（活动 × 日）。托管开启前的数据不计入 AI。先画全年 AI 占比月度曲线，看清波动再下结论。
- **铁律二：不用"整活动分类"。** 不能把"全年被 AI 碰过一次的活动"整条算 AI。AI 侧客单价明显低于人工侧时，说明交给 AI 的多是低价 SKU，账户层数字不能直接下"AI 不如人工"的结论，要看同 ASIN 样本和逐 ASIN 胜率。同 ASIN 取不完就如实标注，不用账户层表面数字。
- **铁律三：ACOS 变化做三因子拆解并验算闭合。** `ACOS比 = CPC比 × (1/转化率比) × (1/客单价比)`，误差 < 0.5%。主因决定动作：CPC 涨 → 补竞价区间、广告位溢价上下限；CVR 跌 → 查商品端（价格、评价、图片、库存、Buy Box）；客单价跌 → 查促销、变体、低价款占比。

### 3. 托管组达标率：三踩二
每个在跑且本期有花费、有销售的托管组，看三个条件，满足 2 个即达标：
1. 销量增长：本期广告销售 > 上期；
2. ACOS 下降：本期 ACOS < 上期；
3. 目标达成：实际 ACOS ≤ 该组目标 ACOS（`aiGroup.targetAcos_`，已是百分数）。

报"达标组 ÷ 评估组"和三踩三 / 二 / 一 / 零的分布。达标率低要拆原因：账户整体收缩时"销量增长"普遍达不成；目标设得比实际还紧时"目标达成"判负。这两种都不等于 AI 效果差。

### 4. 写报告（七段）
顺序：摘要 → AI 应用 → 系统板块使用 → 经营维度切分 → 一句话结论与价值账 → 下一年路线图 → 数据说明。每段的必给指标和写法见 [references/01-七段结构详解.md](references/01-七段结构详解.md)；价值与路线图的对客内容见 [references/03-MCP与服务计划.md](references/03-MCP与服务计划.md)。写作底线与交付验收按 `xnurta-report-standard`。

### 5. 必标的数据边界
1. **不做同比**：超出 MCP 回溯范围，或账户期内才接入。
2. **否词 / 收割价值**：只给次数和样例；"省了多少钱"是反事实，只能标情景估算。
3. **日志覆盖**：操作日志实际回溯不满 12 个月时，写明覆盖的月份。
4. **样本过小**：某店 AI 花费很小时，AI 侧 ACOS 不作为判断依据。
5. **观察性对照**：AI 与人工的比较不是随机分配，只能说"在各自的盘子上表现如何"，不能承诺"开 AI 必降 ACOS"。要因果结论需要受控测试（例如 10–15 个相似父 ASIN，托管组与对照组跑 8 周）。
6. **系统使用数据**：MCP 取不到的写来源或"未取得"。

## 输出

- 一份七段结构的 YBR（在线文档或 Markdown），含全年月度图、AI 占比曲线、维度表、路线图和数据说明。
- 标题建议：「<客户> & SparkX 年度业务复盘报告（YYYY.MM–YYYY.MM）」。
- 不写价格和套餐，不自动发给客户。

## 验收标准

- 12 个月数据完整，月份按顺序排列，没有串年份；缺月份不插值。
- AI 侧 + 人工侧 = 全量；同 ASIN 样本规则和覆盖率写明。
- 三因子闭合误差 < 0.5%。
- 三踩二的分母、分布和低达标原因拆解都在。
- 数据说明写明：每类数据的来源（MCP 工具或用户提供）、为什么不做同比、AI 归属口径、日志覆盖、观察性限制。
- 路线图目标值标注"需运营结合利润 / 库存 / 推广计划确认"。
- **需要业务确认的**：下一年目标、预算、负责人和日期、对外引用的头部案例是否允许使用。

## 异常与已知限制

- **MCP 未连接或无授权店铺**：停止，请用户先完成 MCP 配置。
- **店铺中途解绑**：拆出全年在投的店铺做同口径对比，季度比较用日均。
- **大账户取数慢或被截断**：按店铺、按月分批取；分页按官方 Skill 处理。
- **系统使用、合同、跨客户对标**：MCP 不提供，按对照表第 4 节处理。
- **已删除的托管组**：当前配置查不到，全年建组数结合操作日志估算，或只写当前数并注明。

## 变更记录

- **自然提问**：「帮这个客户做一份 2025.10–2026.09 的年度业务复盘，下个月要谈续约」。
  - **预期**：分 5 段取 12 个月数据，七段报告；不做同比并说明原因；三踩二达标率和 AI 侧 / 人工侧比较都有样本说明。
- **不应触发**：「这个客户续约报价多少合适」，这是商务问题，本技能不写价格。
- **测试状态**：1.1.0 为 MCP 版重写，**未测试，实际输出待补**。1.0.0 内部版本曾在多个客户上跑通，但那些报告含真实客户数据，没有放入本包。
