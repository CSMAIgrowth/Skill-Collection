# 托管组开启时设置检验
对指定不合格组还原本轮开启事件、成员和设置，使用开启前14天数据检查R1/R2，并以开启时预算、分时及竞价设置检查R3。R3命中卡片直接列出触发活动及对应条件。只提供历史设置风险线索，默认交付简短结论和HTML看板。

本版默认生成一份可离线打开的内部HTML，逐组展示开启事件、R1-R3、证据和缺项；完整执行规范中的“用户明确要求HTML时”不再是生成HTML的前提。判断字段与历史还原要求仍按完整规范执行。

## 使用引导

用户不知道怎么用、只说“帮我检查一下”、混淆当前／历史设置或缺少必要上游结果时，先读取[使用建议](references/托管组核验使用建议.md)，主动给出贴近当前任务的示例，并只追问影响执行的缺项。客户、范围、时间和输出方式已明确时直接按本技能继续，不反复要求填表；能只读查到的组ID和开启事件由智能体核对。仅问使用方法时不查询客户数据。引导不扩大名单、阶段或写入授权。

## 按任务读取

- 实际查询、计算或输出正式判定前：完整阅读[执行规范](references/执行规范.md)，再按[公共机制](references/托管组核验公共机制.md)冻结结果、检查质量并交接。不得只凭本页摘要执行判定。
- 仅改已有 HTML 的布局、筛选或措辞：读取公共机制、[错误样本与自检](references/托管组核验错误样本与自检.md)及[项目知识库入口（移植依赖说明）](references/外部依赖与移植说明.md)中的当前交付物，沿用冻结快照；不重新取客户数据。涉及指标、范围或规则变化时仍须读完整执行规范。
- 审阅或修改业务规则：读取完整执行规范与用户当次修订，保留证据和版本关系；不要把结构整理当作改口径。

## 核心边界

- 默认接收上游不合格组；只核验指定名单，不自动扩为全客户。
- 本轮开启时成员和设置、开启前14天窗口必须独立还原；不能用当前设置或三踩一D时集合代替。
- R1/R2/R3独立判断；历史目标缺失仅阻断R2，历史预算或行动空间缺失仅阻断所依赖的R3子规则。可判断的规则继续。未发现规则风险不等于设置全面正确。
- 指定D未必等于本轮开启日；交接须核对真实开启事件，不能把不同锚点自动视为同一事件。见[待核对项](references/待核对项.md)。

仅修订、审阅或导出 Skill 时不运行客户分析。查询与起草不授权改广告、写 Jira 或外发消息。用户指出错误时，同轮更新对应样本；交付前按相关样本自检，静态通过不代表浏览器行为通过。

完整执行规范是本技能业务细节的主维护位置；本页仅作路由和必要摘要。旧版同领域 Skill 的本项目适用状态以项目知识库入口为准，不改动其他项目或已安装插件。
