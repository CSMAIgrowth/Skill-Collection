# OOB 统计和损失估算

> 公开版说明：案例标识、经营数据及操作轨迹已移除；数值示例为独立构造的虚构演示或字段占位，不代表真实客户结果。诊断时须使用当前授权数据，不能套用示例结论。


## OOB 判定

**优先使用平台直接事件：** 操作日志中 `operationType = Campaign Out of Budget` 的记录，保留精确发生时间。这类记录是平台状态事件，不是人工操作。

小时数据只作辅助：

```
辅助信号（不能单独确认 OOB）：
    某小时 spend = 0
    且该小时之前累计 spend ≥ 当时预算上限 × 0.95
    且前后存在预算耗尽/预算回补日志
```

`spend=0` 也可能由竞价过低、流量不足、投放暂停或数据归因延迟造成。预算随时间变化时，必须使用当时回放的预算上限，而不是固定日预算。

## OOB 统计表

必须按时段展示：

```
时段    OOB天数  总天数  OOB占比  高峰/非高峰  损失订单(估算)
{时段}  {天数}   {天数}  {占比}   {分类}       {日均差值}
```

**标注**：OOB天数 = 该时段发生OOB的天数；总天数 = 分析期总天数；损失订单 = 基准期时段日均订单 - 托管期时段日均订单。

## OOB 损失估算

```
单时段损失：
    订单损失 = 基准期时段日均订单 - 托管期时段日均订单
    销售额损失 = 订单损失 × 客单价
    花费损失 = 基准期时段日均花费 - 托管期时段日均花费

总损失：
    总订单损失 = Σ(各时段订单损失)
    总销售额损失 = Σ(各时段销售额损失)
```

## OOB 集中度分析

```
高峰OOB占比 = 高峰时段OOB天数 / 总OOB天数

判定：
    高峰OOB占比 > 50% → 结构性问题（预算分配错误）
    高峰OOB占比 < 30% → 日预算整体不足
```

## 可视化

1. **OOB 热力图**：横轴=小时，纵轴=日期，颜色=是否OOB
2. **OOB 损失柱状图**：横轴=时段，纵轴=损失订单数
3. **高峰 vs 非高峰 OOB 饼图**：展示OOB时间分布

## 与操作对齐

逐条回放 `DailyBudget Increased/Decreased` 的 `previousValue → newValue`，重建每日预算阶梯，并把 OOB 事件放在曲线上：

```
预算轨迹：{时间1} $A→$B → {时间2} $B→$C → ...
OOB：{实际事件时间1} / {实际事件时间2} ...
高转化窗口：由基准期分小时订单和 CVR 定义
```

- OOB 发生在操作后：检查操作是否改变预算释放节奏。
- OOB 发生在操作前：OOB 不是该后续操作的结果。
- 不要仅凭“某日有一次配置变更”推断策略切换；若配置日志没有明确切换记录，写“从操作回放观察到行为变化”，标注推断等级。
- 检查高转化窗口内是否断档、恢复后花费转移到哪些小时，以及是否存在预算恢复后 CVR 同步恢复的反向验证。
