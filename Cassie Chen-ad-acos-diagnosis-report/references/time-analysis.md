# 日级和小时级异常定位方法

> 公开版说明：案例标识、经营数据及操作轨迹已移除；数值示例为独立构造的虚构演示或字段占位，不代表真实客户结果。诊断时须使用当前授权数据，不能套用示例结论。


## 日级异常定位

### 步骤

1. **列出每日关键指标**

```
日期        单日总花费  单日总订单  CVR    ACOS    操作事件
{日期}      {花费}      {订单}      {CVR}  {ACOS}  {日志事件}
```

2. **计算3日滚动ACOS**

```
3日滚动ACOS(d) = (花费(d-2)+花费(d-1)+花费(d)) / (销售额(d-2)+销售额(d-1)+销售额(d))

异常起点 = 第一个3日滚动ACOS > 目标ACOS 且 CVR < 基准期CVR×80% 的日期
```

3. **与操作日志对齐**

在异常起点前后±2天范围内查找操作事件。

### 时间线展示

用表格展示，包含：
- 日期
- 总花费（标注"总"）
- 日均订单（标注"日均"）
- CVR
- ACOS
- 操作事件（AI/人工）

## 小时级异常定位

### 触发条件

满足以下任一才做小时分析：
- 日级数据无法解释恶化原因
- 存在分时预算/竞价操作
- OOB suspected（日级花费波动异常）

### 步骤

1. **计算每个小时的时段日均**

```
对每个小时 h（0-23）：
    时段日均花费(h) = Σ(每天h时的花费) / 天数
    时段日均订单(h) = Σ(每天h时的订单) / 天数
    时段CVR(h) = Σ(每天h时的订单) / Σ(每天h时的点击)
```

2. **标记高峰/低谷时段**

```
平均每小时订单 = 基准期总订单 / (基准期天数 × 24)
时段每小时订单(h) = 基准期该小时总订单 / 基准期天数

候选高峰小时 = {h | 时段每小时订单(h) ≥ 平均每小时订单 × 1.5 且点击达到最小样本量}
高转化窗口 = 相邻候选高峰小时合并后的连续时段
```

同时复核该窗口 CVR。不要预设上午/下午为高峰，也不要用“小时订单 > 全天日均订单”这种量纲不一致的比较。

3. **比较两期可比窗口**

```
窗口花费保留率 = 托管期窗口日均花费 / 基准期窗口日均花费
窗口订单保留率 = 托管期窗口日均订单 / 基准期窗口日均订单
窗口 CVR = 窗口总订单 / 窗口总点击
```

若小时数据只有 7 天窗口，明确写出两期各自的起止日期、总花费和总订单，防止把窗口选择偏差当成机制。

4. **计算经济损失**

```
对每个小时 h：
    经济损失(h) = 时段日均花费(h) - 时段日均销售额(h) × 目标ACOS

按经济损失从高到低排序，取Top 5时段
```

5. **复核指标**

```
时段订单损失 = 基准期时段日均订单(h) - 托管期时段日均订单(h)
时段CVR变化 = 托管期时段CVR(h) - 基准期时段CVR(h)
```

6. **与操作对齐**

检查Top异常时段是否有对应的操作（预算调整、竞价调整）。把“操作发生的小时分布”与“基准高转化窗口”叠加，而不只检查异常日前后±2天。操作作用于全天时，继续还原具体生效小时和预算阶梯。

### 展示格式

```
小时    基准期时段日均花费  托管期时段日均花费  变化      基准期时段日均订单  托管期时段日均订单  变化      OOB天数
{时段}  {基准花费}          {托管花费}          {变化率}  {基准订单}          {托管订单}          {变化率}  {天数}
```

**必须标注**：所有数值均为"时段日均"（该时段总计÷天数）。
